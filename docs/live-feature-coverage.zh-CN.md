# 实时数据功能覆盖

本文说明 LootWeave 面向 Deskrawl 线上模式的自有实时观测模型。
本文描述源码能力，不代表已实现完整游戏功能或通过实机验收。

Rust 负责原生采集、桌面功能和进程生命周期。
Python 负责 API、OCR 处理、统计和存储。React 呈现观测和复核界面。
Windows 应用仍以单个 EXE 为启动入口，并随包提供 Python 服务。

## 数据视图

| 视图 | 当前模型与行为 | 限制 |
| --- | --- | --- |
| 角色 | 样本可包含身份、等级、经验、生命、法力、区域、地图和巅峰数据。 | 数值由数据源提供。缺失值保持未知。Deskrawl 范围由样本声明，未独立验证。 |
| 装备与容器 | 样本可包含已装备物品、背包、仓库、马车、词条、单位、roll区间、强化、孔位和镶嵌物。 | 界面只显示实际收到的观测。物品标记缺失时保持未知。孔内物品和效果需要来源证据。 |
| 构筑 | 样本可包含技能、天赋、巅峰、符文、随从和临时效果。 | 已提供的等级或标识不能证明游戏机制或隐藏分配。 |
| 观测面板 | 样本可包含基础属性、最终属性、校验和观测面板值。 | 观测值与估算值分开。不证明实战伤害或换装收益。 |
| 资源 | 来源提供时，界面可显示材料、药剂、容量、仓库页、拾取设置和警报。 | 缺失数量和设置保持未知。不根据缺失推断数值。 |
| 跑图报告 | API 最多接收1000条跑图记录。速率最多使用20条近期记录，且要求 `partial: false`、完整耗时、经验和金币。 | 地图汇总只描述收到的数据，不推荐最优路线。缺少报告时显示“未采集”。 |
| 实战伤害 | API 最多接收8192条伤害事件。仅对完整时间窗计算10秒和60秒 DPS。 | 缺失或 partial 时间窗保持未知。没有事件时显示“未采集”。 |
| 血脉记录 | API 最多接收5000次抽取和2000条发现记录。界面只报告观测频次。 | 频次不预测下一次抽取，也不是游戏概率。缺少输入时显示“未采集”。 |
| 配装参考 | 界面可只读展示五个配装位置及来源提供的技能、装备和缺失物品。 | 缺失位置和标记保持未知。LootWeave 不会更改游戏装备。 |
| 状态与定义 | 来源提供时，界面可显示目录、事件和静态定义。LootWeave 保留自有知识包缓存。 | 界面只显示已收到的数据。缺失目录和机制保持未知。 |

模型还会分开城镇清单、地面物品、运输、预览和宝箱内容。
这些记录不会与已持有装备混合。
预览不代表所有权、掉落概率或未来物品。

## 自有 API 与存储

协议为 `lootweave-live/1`。
Gateway 使用当前会话，接收 `POST /api/profile/live/samples`。
原始 JSON 上限为4 MiB。
样本包含来源标识、上下文、职业、采集时间、角色、物品、装备槽和覆盖信息。
可选字段包括概览、构筑数据、报告和报告覆盖信息。

`GET /api/profile/live/sources` 列出已收到的来源。
`POST /api/profile/imports/live/read` 将来源绑定当前会话并冻结预览。
`POST /api/profile/imports/live/draft` 根据该预览创建草稿。

样本缓存和预览缓存各最多保存16条、8 MiB，保留600秒。
同一来源的新样本会替换旧样本。
API 拒绝时间倒退的样本，以及同一毫秒内相互冲突的样本。
轮询和发布样本不会写入 SQLite。
创建草稿时保存冻结来源。用户明确确认后才创建快照版本。
覆盖信息缺失不代表背包为空。物品标记和配装位置缺失时保持未知。

## OCR 与采集

界面可载入本地 JSON 观测文件。
capture-observation 功能也可载入本地 BMP 文件，最大6 MiB、1600×1200像素。
仅接受未压缩的24位或32位 BMP。
Python 使用现有 OCR 流程，Profile 将原始观测保存为未确认状态。
实际截图时间未知时，观测继续保留未知时间。
Windows OCR 模型需要 Windows。

原生截图仍由 Rust 执行。
OCR 只识别当前演示解析器支持的可见字段。
OCR 无法读取隐藏内存或隐藏游戏状态。
目前没有自动游戏内存采集器或官方游戏 API。

## 统计与解释

Python 根据收到的记录和事件计算统计。
统计只描述已提供的样本窗口，不推断缺失的游戏数据。
完整跑图速率以经验和金币总量除以完整耗时总和。
实战伤害以完整的10秒或60秒窗口计算。
血脉报告只显示观测频次。
这些计算不证明完整机制、最优路线或物品概率。

十个视图和宽泛的数据模型，不代表 LootWeave 会自动采集或验证所有游戏功能。
Deskrawl 线上实机采集、完整字段覆盖和游戏机制仍未验证。

## 当前自有 API 响应量测量

本次测量使用虚构的持有物品样本和当前自有 API 实现。
Python 在临时存储中调用 Profile 处理函数。测量紧凑 UTF-8 响应正文。
未测量 CPU、总内存、帧率或端到端延迟。

| 持有记录 | 完整读取 | 内容未变读取 | 正文减少 |
| ---: | ---: | ---: | ---: |
| 80 | 49502 字节 | 549 字节 | 98.89% |
| 800 | 451985 字节 | 552 字节 | 99.88% |
| 1500 | 843288 字节 | 555 字节 | 99.93% |

响应优化不减少采集端输入量。
报告内容会改变响应大小和内容哈希。
